# Screens group B - findings (src/ESP32-HAM-CLOCK.cpp, line numbers cite that file)

## 0. Cross-cutting facts (apply to every screen below)

- Display 320x240, TFT_eSPI built-in 6x8 font scaled with setTextSize(n) (char cell = 6n x 8n px). Smooth VLW fonts (data/fonts/Roboto10/12/20.vlw, 23/29/58 KB) are used only in a few places: weather description + weather labels (Roboto12, L10317), weather alert text in APRS alert (L12439), Roboto20 elsewhere. Fallback to built-in font when LittleFS/font missing.
- Colors: `tftUiPalette {bg,fg,muted,accent,rowAlt}` (L850-860, applyTftUiPalette L1118). Dark: bg BLACK, fg WHITE, muted LIGHTGREY, rowAlt 0x0841. Light: bg WHITE, fg BLACK, muted DARKGREY, rowAlt 0xDEFB. `accent` = `menuThemeColor` = `TFT_RADIO_ORANGE` macro (L4388) = colorWheel(menuThemeHue) (user-configurable hue, default 0xFD20 orange). Most header bars use this theme color. `tftStyleMode` dark/light (L851); in light mode most coloured values collapse to fg black. `tftLanguage` TFT_LANG_PT_BR(0)/TFT_LANG_EN(1) selects labels (tr() tables L940-980).
- Screen order (user-reorderable, persisted) `screenOrder[]` L702: HAM_CLOCK, DX_CLUSTER, APRS_IS, APRS_RADAR, BAND_INFO, SUN_SPOTS, WEATHER_DSP, WEATHER_FORECAST, POTA, HAMALERT, MATRIX_CLOCK, LOKALIZACJA (12 pages). SCREEN_UNLIS_HUNTER is NOT in the order; reachable only via hidden gesture from matrix clock. Entries may be SCREEN_OFF (disabled). getNext/PrevScreenId L6665/L6676 skip OFF.
- Draw architecture: `drawScreen(ScreenType)` L4081 runs only on UI task (`uiTaskLoop` L17890, 10 ms vTaskDelay loop); other tasks call `requestUiScreenRedraw`. fillScreen with palette bg (pure BLACK for MATRIX & UNLIS), then dispatch. Incremental refresh pattern: every screen has `updateScreenNData()` that computes an FNV-1a signature of the displayed data and only redraws the body when it changes; header clock is repainted separately each time the minute/second string changes. LVGL equivalent: bind labels to data, update on change.
- Global touch (handleTouchNavigation L6706, runs in uiTaskLoop each 10 ms; 150 ms debounce between taps; reads XPT2046 raw -> mapRawToScreen):
  - When not in a screen-specific menu/zone: tap bottom 180 px band (y >= 60): left 80 px (x<80) -> previous screen; right 80 px (x>=240) -> next screen; centre (80<=x<240) -> pause autoswitch 10 s. (L6990-7010). Top 60 px is reserved for per-screen buttons.
  - Hold touch >= 3000 ms anywhere (not in game) -> brightness menu (L6741). Hold >=2000 ms starting in top-right zone (x>=240,y<=80) on MATRIX_CLOCK -> enters UNLIS_HUNTER (L6733).
  - aprsAlertScreenActive swallows all touch except the close button (L6728).
  - Autoswitch (tftAutoSwitchEnabled, tftAutoSwitchTimeSec) rotates to next screen; disabled in UNLIS, menus, alerts (L17951).
- "Table nav footer": for APRS_IS, WEATHER_DSP, WEATHER_FORECAST (plus DX/POTA/HAMALERT) a footer "<  SWITCH SCREEN  >" (two triangles at (10,230)/(310,230) + text at (125,226), colour 0x52AA) is shown only 5 s (TABLE_NAV_FOOTER_VISIBLE_MS) after entering the screen (L795-830, drawSwitchScreenFooter L818); table gets 10 rows while visible and 11 when hidden (table bottom 220 vs 240).
- Hamburger menu icon: drawHamburgerMenuButton3D(x,y) L7158: 26x23 rounded orange button with 3 black bars, drawn at (5,7). Hit zone for menus is 50x50 at the top-left (menuHitW/H L6711).

## 8. SCREEN_UNLIS_HUNTER (11) - mini game  [consts L742-766; functions L10995-11630; drawUnlisHunter L11540; updateUnlisHunter L11559; touch L6797]

- Purpose: easter-egg radio direction-finding game: "UNLIS HUNTER GAME" (Unlis = unlicensed): "Use a Yagi antenna to catch and jam its signal by pressing PTT on it."
- Geometry: radar centre (160,120); outer ring R=115 YELLOW ("2m" band), inner ring R=60 BLUE ("70cm"); centre dot GREEN r3. Yagi pointer = rotating line: yellow line from centre to outer ring at angle theta (0 deg = up, clockwise), blue line from centre to inner ring at theta+180 deg (opposite side). Pointer tip hits target when it lies within hitPx=14 px of a target on the same ring (outer target uses the yellow tip, inner target the blue tip).
- Buttons (100x100 touch squares, drawn as 50x50 black rounded buttons with white/grey bevel, size2 label): START/STOP at top-left (0,0) [label "STOP" while running, else "START"], PTT bottom-right (220,140), EXIT bottom-left (0,140).
- HUD: score at (4,56) size2 GREEN 3 digits zero-padded (unlisCaught); three miss markers (circles r5, x=12, y=102/120/138; red filled for misses, dark-grey outline when not missed); "BAND:" legend size1 at (286,96) with "2m" yellow (292,108) and "70cm" blue (286,120); timer top-right "<sec>s" size2 white right-aligned to x=316,y=6.
- States: INTRO (not running): fills black, draws buttons+HUD+intro box (rect 40,72,240x92 with title yellow size2 "UNLIS HUNTER GAME" and three size1 white lines). RUNNING. ## 13. Surprises / migration risks

1. Screen 3 = "PROPAGATION" (solar) and screen 4 = "HF BAND INFO"; names "SUN_SPOTS/BAND_INFO" do not match but are correct per enum. Screen 4 title is not translated; screen 3 clock is UTC with "Z", others use timezone.
2. APRS list and radar are separate screens; view-toggle button and Screen6ViewMode are dead code. Radar intro animation for matrix is dead code.
3. APRS menu: CLOSE saves current globals (discarding temp changes), SAVE applies temps; sort mode is applied instantly and never persisted; menu text is English only.
4. Forecast screen has only 4 visible columns even though 5 slots fetched.
5. Weather alert "Repeat: N min" displays eta hours as minutes (bug-ish). APRS alert WX label "WIATR" is Polish and untranslated; boot start lines Polish.
6. Rendering is immediate-mode with many manual rect clears; some updates use a shared TFT_eSprite (ensureSharedTableSprite) - LVGL should replace with widgets/tables + a canvas for radar/game/matrix.
7. Radar computing uses 11-station cap and sort order, distance filter by aprsFilterRadius, zoom only scales px not data filtering.
8. Weather and APRS-alert call paths: ALERT_Screen/WEATHER_ALERT_Screen are drawn from UI task via pending flags, but APRS_BEACONING_Screen is called directly from the TX code path (cross-task TFT access) - with LVGL needs lock/queue.
9. Touch while `aprsAlertScreenActive`: everything swallowed except close X; 3 s long press still can open the brightness menu on any screen except it is checked before the UNLIS handler (hold on game would open it).
10. Unlis hold-gesture: only on matrix clock top-right region x>=240,y<=80, 2 s; no on-screen hint.
