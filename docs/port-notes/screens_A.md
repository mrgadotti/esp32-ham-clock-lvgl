# Screen group A findings (all line refs: src/ESP32-HAM-CLOCK.cpp)

Hardware/runtime: ILI9341 320x240 landscape (tft.setRotation(tftRotation=1)), XPT2046 on its own SPI (CS33, IRQ35, MOSI32, MISO27, CLK25; L602-690). All UI runs in one FreeRTOS task `UI_Task` (8192 stack, prio 2, core 1; created L18212) executing `uiTaskLoop` (L17890). Rendering is immediate-mode TFT_eSPI (fillScreen + redraw); no widget tree. drawScreen() (L4081) called from another task is converted to a deferred request (requestUiScreenRedraw L11589) handled by uiTaskLoop.

## Shared chrome

### Screen order / navigation
- ScreenType enum L533. Order array `screenOrder[12]` (L615) default: HAM_CLOCK, DX_CLUSTER, APRS_IS, APRS_RADAR, BAND_INFO, SUN_SPOTS, WEATHER_DSP, WEATHER_FORECAST, POTA, HAMALERT, MATRIX_CLOCK, LOKALIZACJA. UNLIS_HUNTER (11) is NOT in the order (hidden game, enter by 2 s hold top-right (x>=240,y<=80) on MATRIX screen, L6740-6770 region; exit by bottom-left box).
- Order persisted as raw bytes NVS key `screen_order` (12 bytes), editable via web API (screen_order array of codes: hamclock,dxcluster,aprsis,aprsradar,bandinfo,sunspots,weather,weatherforecast,lokalizacja,pota,hamalert,matrix,unlishunter; L6590-6640). A slot set to SCREEN_OFF is skipped (disabled screen); duplicates removed (ensureScreenOrderValid). Boot screen = first active in order.
- Navigation: handleTouchNavigation (L6706), called every UI loop (10 ms delay). Tap zones (screen coords after mapping), only on a NEW touch (isNewTap; 150 ms re-touch debounce):
  - left zone x<80 && y>=60: previous screen; right zone x>=240 && y>=60: next screen (wrap-around, skipping OFF); center (80<=x<240, y>=60): pause autoswitch 10 s (`autoswitchPausedUntilMs`). Top strip y<60 is reserved for per-screen buttons (hamburger/menu etc.), so left/right nav only works below y=60.
  - Any nav resets autoswitch timer and clears the pause.
- drawNavigationArrows (L11585) is an EMPTY stub (dead). Arrow triangles are drawn per screen: HAM_CLOCK draws two filled triangles at (10,230,20,222,20,238) and (310,230,300,222,300,238) in accent color permanently (L4955). Table screens use drawSwitchScreenFooter (L818): same two triangles in menuThemeColor + grey 0x52AA text "SWITCH SCREEN" at (125,226), shown only for 5 s after entering the screen (TABLE_NAV_FOOTER_VISIBLE_MS L767; set in drawScreen when screen changed L4093 for isTableFooterScreen: DX, POTA, HAMALERT, APRS_IS, WEATHER_DSP, WEATHER_FORECAST). While footer visible, table is clipped to y<220 (TFT_TABLE_BOTTOM) and max rows drop 11->10 (normal) / 7->6 (enlarged) (getTableMaxRowsForScreen L788, getDxTableMaxRows L1049 etc.). Note: footer is only drawn on a full redraw; its 5 s expiry is not actively erased by a timer (the next data-signature change redraws with the extra row; signatures include navVisible bit).
- Auto-switch (uiTaskLoop L17943-17975): enabled by NVS `tft_autosw` (bool, default false), interval `tft_sw_sec` (int, default 30, clamp 1..3600; set by web "tft_auto_switch"). Skipped when inMenu, alert screen, touchCal, brightness menu, UNLIS. Timer resets when screen changes; next screen via getNextScreenId. No on-device UI to configure autoswitch (web only).
- Alert overlays (APRS alert, weather alert) preempt via aprsAlertScreenActive: touch handled only to dismiss (out of group A scope).

### Touch pipeline / calibration
- readRawTouchPoint (L6501): touch.touched()+getPoint() raw 12-bit. mapRawToScreen (L6539) -> mapRawToScreenWithValues (L6511): optional swapXY, then invertX: mx = xmax-(mx-xmin), invertY same; constrain to [min,max]; x = map(mx,xmin,xmax,0,tft.width()-1), y likewise with height. Defaults xmin/xmax/ymin/ymax = 200/3800/200/3800, swap/invX/invY false. Also touch.setRotation(touchRotation) (default 1) is applied in the driver in addition (applyTouchRotation L3815) -> double-rotation system (library rotation + swap/invert flags). Whatever LVGL indev driver is written must reproduce raw->screen exactly or fold both.
- NVS (namespace "dxcluster", L16627-16637 / 16807-16815): touch_xmin, touch_xmax, touch_ymin, touch_ymax (int, validated 0..4095, min<max else defaults), touch_swap, touch_invx, touch_invy (bool), touch_rot (uchar 0..3, default 1), tft_rot (uchar 0..3, default 1), tft_inv (bool, default from -DTFT_INVERSION_ON).
- On-device calibration (drawTouchCalibrationScreen L8085, startTouchCalibration L8190, handleTouchCalibrationTouch L8224): reached from brightness screen by holding anywhere >=5 s (handleBrightnessMenuTouch L8335; menu must be open >1.5 s). 4-point: steps 0..3 targets at (20,20) TL, (300,20) TR, (300,220) BR, (20,220) BL (crosshair+24px square in menuThemeColor), prompt text "Touch target n/4 (...)" (hardcoded English, not in tr()). Raw captured on each new tap. After 4th: newXMin/Max, newYMin/Max = min/max over 4 raw points; swapXY = (rangeY > rangeX); with swap applied to p1/p3, invertX = (x3<x1), invertY = (y3<y1). Step 4 review screen shows raw min/max, detected Swap/InvX/InvY, a hint "Use WWW panel >" + suggested mode name (xy_both / rot90cw / rot90ccw / xy / both(180deg) / x / y / none), and "(Touch will NOT save changes)". Any touch then restores swap/invX/invY to compile-time defaults (L8297-8300), leaves touchXMin... untouched, and returns to the brightness menu. NET EFFECT: on-device calibration is only a diagnostic; nothing is persisted or applied (min/max never copied to touchXMin etc.). Real config via web: "touch_swap_mode" (none/xy/x/y/both/rot90cw/rot90ccw/xy_both L17449), touch_rotation, tft_rotation; reset-to-defaults API at L17638/17755. TR_ROT_90_*/TR_TFT_CALIBRATE_BTN keys: ROT_90 used only in review screen; TFT_CALIBRATE_BTN and TR_HOLD_CAL_HINT unused (dead). TR_TFT_CALIBRATION_HINT says "Hold 5 sec" (EN) while the hint text on the brightness screen is the same string; real thresholds: 3 s opens brightness menu, 5 s inside it opens calibration (comment at L8048 says 3s - inconsistent).

### Brightness / theme / language menu ("DISPLAY SETTINGS")
- Open: hold anywhere >=3000 ms on any screen (not UNLIS, not during cal/alert) (L6779). Saves prev screen, inMenu flag, backlight, hue, style for Close/restore. Sets inMenu=true & brightnessMenuActive. Ignores touches for first 1500 ms except the style button.
- Layout (drawBrightnessMenu L8044): header bar 0..28 in menuThemeColor with title tr(TR_DISPLAY_SETTINGS) size 2 black and, at (248,4,68x20) rounded button showing "DARK"/"LIGHT" (EN) or "ESCURO"/"CLARO" (PT); hit area x>=205,y<44; tap toggles tftStyleMode (dark<->light) and applyTftUiPalette immediately. Hint text at y=40. Brightness slider x40..280, y90 (h12; hit y 84..108), shows "BRIGHTNESS: nn%" ; value range MIN_BACKLIGHT_PERCENT=10..100 (L626), live preview via setBacklightPercent. Theme slider y130 (hit 124..148): gradient of colorWheel(hue) over 240 px; hue 0..255 (uint8) -> menuThemeColor=colorWheel(hue) (L4366-4385: reversed wheel, 3 segments of 85, rgb565). Default hue 20 (0xFD20 orange). Language tiles "EN" / "PT-BR" at y160 (70x22, centered, gap 10). Buttons y190 (90x26): SAVE (x10), DEFAULT (x115), CLOSE (x220).
- SAVE: backlightPercent=slider value; savePreferences() (saves everything incl hue, style, lang); exit & redraw prev screen. DEFAULT: only resets hue to 20 (not brightness, not style, despite label). CLOSE: reverts backlight, hue and style to pre-menu values and exits (language change is NOT reverted - saved immediately on tap).
- Language tap: sets tftLanguage, invalidates weatherData (valid=false, forecast flags, detailValid[]) and lastWeatherFetchMs=0 to refetch localized weather text, savePreferences, redraw menu.
- NVS: tft_backlight (int 10..100, default 100), tft_style (uchar 0 dark,1 light; code strings "dark"/"light"), menu_hue (int 0..255), tft_lang (uchar 0=PT_BR,1=EN; codes "pt-br"/"en"), tft_ndim (night dimming %, 0..100), tft_tbl_size (0 normal / 1 enlarged), screen1_time (0 UTC /1 local).
- Backlight: LEDC PWM on GPIO TFT_BL (21), 5 kHz, 8 bit (setupBacklightPwm L3726; both Arduino-core 2.x and 3.x APIs handled). writeBacklightPwmPercent clamps to [10,100], duty=percent*255/100. Night dimming (L3775-3805): if weather valid and weatherData.iconCode ends with 'n' (OpenWeather night icon) and tftNightDimmingPercent>0: target = base*(100-dim)/100, floor 10. If icon ends 'd' or no weather -> base. applyBacklightByDayNight(force) is a no-op while tftInitialized false or brightness menu active; interval const BACKLIGHT_DAY_NIGHT_CHECK_INTERVAL_MS=5 min declared (L631). tft_ndim only settable via web ("tft_night_dimming" L17223). setBacklightPercent also applies night dimming.
- TFT rotation / inversion: applyTftRotation (tft.setRotation), applyTftInversion (tft.invertDisplay(tftInvertColors)); both only configurable via web (tft_rotation, tft_invert L17228) + NVS; menu has no UI for them.

### Palette / theme
- TftStyleMode dark/light. applyTftUiPalette (L1118): accent = menuThemeColor; dark: bg BLACK, fg WHITE, muted LIGHTGREY, rowAlt 0x0841; light: bg WHITE, fg BLACK, muted DARKGREY, rowAlt 0xDEFB. Helpers (L1075-1105): header bg = accent; header text = fg(light)/BLACK(dark); table freq color = YELLOW (dark) / fg (light); mode color GREEN (dark) / fg (light); table accent text (MSG/country) = menuThemeColor (dark) / fg (light). TFT_RADIO_ORANGE is a macro = menuThemeColor (dynamic). Filter menus and brightness menus ignore light theme (always black bg, drawFilterTile active = menuThemeColor fill / black text, inactive = DARKGREY fill / white text, black 1px border; L7430).
- NO band colors, NO age colors anywhere in groups HAM_CLOCK/DX/POTA/HAMALERT: only the 5 semantic colors above plus TFT_RED "WAITING FOR SPOTS..." (size 2, at x40,y120) when no rows.

### Language / string table
- Only two languages: PT_BR (default) and EN. Table-based for a few keys: enum TrKey (26 keys, L908) with `TR_EN[]` and `TR_PT_BR[]` arrays of const char* (L933-994), lookup tr(key). Keys: Time, Call, COUNTRY, Waiting for spots, WEATHER, TEMPERATURE, HUMIDITY, PRESSURE, WIND, Forecast 3h, Forecast tomorrow, No data, ERROR:, Page, calibration hint, calibrate btn, rot90 right/left, DISPLAY SETTINGS, BRIGHTNESS, THEME COLOR, hold hint, SAVE, DEFAULT, CLOSE, LANGUAGE. Everything else is hardcoded English literals or inline `isEn ? .. : ..` ternaries (date line, "Local Time"/"Hora Local", dark/light label, SALVAR). In group A, only TR_COUNTRY ("COUNTRY"/"PAIS") appears in table headers (POTA, HAMALERT). Other column headers (UTC, CALLSIGN, MHz, MODE, MSG), filter-menu titles (FILTERS/POTA FILTERS/HAMALERT FILTR [sic]/TIME MODE) and band tile text are NOT translated. Polish remnants in comments/logs only. Date strings with accents use Roboto20.vlw smooth font from LittleFS (/fonts/Roboto20.vlw; Roboto10/12 defined but only 20 loaded for date); fallback to built-in size-2 font with sanitizePolishToAscii. Weekday/month names functions getEnglishDateStringFull / getPortugueseDateStringFull (+WithTimezone) L4660-4701.
- Text rendering is TFT_eSPI built-in 6x8 GLCD scaled (size1 = 6 px/char, size2 = 12, size 4 = 24); no other fonts in group A except the date line.

### Table-size mode (DxTableSizeMode, L862, NVS tft_tbl_size)
- One global switch affects DX, POTA, HAMALERT, APRS_IS tables (not HAM_CLOCK). NORMAL: text size 1, row pitch 17 px, columns incl. message/country; max rows 11 (10 when nav footer showing). ENLARGED: text size 2, row pitch 27 px, only 4 columns (UTC, CALL, MHz, MODE; callsign cut to 9 chars, mode to 4), max 7 rows (6 with footer). Set via web ("table_size": normal/enlarged or big/large). Not changeable on device.

## SCREEN_HAM_CLOCK (1)
- Purpose: big station clock with callsign, date and connectivity status.
- Draw (drawHamClock L4865), bg = palette bg:

There is NO hamburger icon here (a comment mentions menu icon); the menu hit zone is top-right x>285 && y<35.
  - Rounded frame (10,50,300x155,r8), color DARKGREY (dark) / BLACK (light).
  - Callsign (userCallsign upper-case, default "SWL") size 4 centered at y65; "OPERATOR STATION" size 1 accent color at (110,105) (hard-coded English).
  - Clock size 4 `HH:MM:SS` centered x in frame at y125: UTC (getUtcTimeString) or local-with-TZ (getTimezoneTimeString("%H:%M:%S")) per screen1TimeMode. Label below at y165: "UTC" or "Local Time"/"Hora Local".
  - Date line (Roboto20 smooth font, centered, y178, area cleared 173..bottom): UTC mode -> "Weekday dd/mm/yyyy"-style full string (EN or PT-BR); local mode with timezone variants. Falls back to size 2 if text wider than 290px.
  - Bottom: IP address size 2 centered at y215 (STA IP, or softAP IP if AP mode), light-grey (BLACK in light); else red "NO CONNECTION" at (80,215) (black in light theme).
  - Connection indicator circle at (50,222): green dot r4 = connected (STA or AP), red dot r4 = not; every 4 s for 2 s (millis%4000<2000) it becomes a green r12 badge with "GPS" text when UART2 GPS parsing enabled && GPS UART active && FIX (L4816-4863).
  - Nav arrows triangles bottom corners always visible (accent color).
- Data: userCallsign, wifiConnected/WiFi.status, system time (NTP or GPS-synced), GPS flags (isUart2GpsParsingEnabled, isGpsUartActive, isGpsFixActive), screen1TimeMode, tftLanguage.
- Refresh: uiTaskLoop: updateScreen1Clock every >1000 ms (clears only clock box x/y 120..155, redraws time and indicator); updateScreen1Date (only when day changes); updateScreen1Header. Full redraw on screen entry or updateScreen1() (IP change, L11641).
- Touch: tap top-right x>285,y<35 -> TIME MODE menu (drawHamClockTimeMenu L7884): title "TIME MODE", two tiles 110x28 at y60: "UTC" and "LOCAL" (selected = accent), tap sets screen1TimeMode and savePreferences (NVS screen1_time) immediately; CLOSE tile (100x26 at (110,210)) -> redraw screen. Plus global nav/long-press.

## SCREEN_DX_CLUSTER (2)
- Purpose: live DX cluster spot table (telnet cluster, default dxcluster.iu1bow.it:7300 (LVGL port; original was dxspots.com)) with mode/band filters and scrolling.
- Data: global `DXSpot spots[MAX_SPOTS=100]`, `spotCount`, newest first (addSpot shifts array; L14256), guarded by dxSpotsMutex (lockDxSpots). DXSpot fields: time (string), spotter, callsign, frequency (kHz), comment, distance(km), country (QRZ), locator, lat/lon/hasLatLon, band("160m".."10m"/"Other" via getBand L13357), mode (CW/FT4/FT8/SSB default from comment, getMode). Country/lat-lon filled asynchronously by QRZ lookup queue (2 s interval on this screen, L1359). updateScreen2() requests a redraw when new spots/QRZ updates arrive (L13992).
- Header (drawDxCluster L6560 region): 0..32 filled accent; 3D hamburger button (drawHamburgerMenuButton3D at (5,7), 26x23 rounded, 3 black bars); text `clusterHost` (size 2 at x35,y8, e.g. "dxspots.com"); UTC time "HH:MM Z" right-aligned (size 2, ends x315), updated at most every 5 s (DX_SCREEN_MIN_REDRAW_MS) by updateScreen2Clock.
- Column header row at y40 (size 1, muted) + hline at y50. NORMAL: UTC@5, CALLSIGN@53, MHz@113, MODE@167, MSG@197. ENLARGED: UTC@5, CALL@74, MHz@191, MODE@274. Rows alternate rowAlt background (even index).
- Row content NORMAL: formatSpotUtc(time) HH:MM (muted); callsign (fg, max 10 chars DX_CALLSIGN_COL_MAX_LEN); frequency/1000.0 with 3 decimals in MHz (yellow/dark); mode (green/dark); MSG = spot.comment trimmed, max 20 chars (MESSAGE_COL_MAX_LEN), "-" if empty (accent). NOTE: DX uses comment, not country (country is only used in POTA/HAMALERT). Distance not shown.
- Rows: 11 normal (10 w/ footer), 7 enlarged (6). Empty: red "WAITING FOR SPOTS..." size 2.
- Filters: screen2FilterModeMask (bit CW=1, SSB=2, DIGI=4 (FT8/FT4); 0=ALL) and screen2FilterBandMask (16-bit; bit i-1 for band index i in SCREEN8_FILTER_BANDS[12]={ALL,160m,80m,40m,20m,17m,15m,12m,10m,VHF,UHF,SHF}; 0=ALL). Multi-select (toggle bits). Note 30m and 6m/60m bands do not exist as filter tiles though getBand returns "30m". VHF 30..300, UHF 300..3000, SHF 3000..30000 matched on freq value (compares spot.frequency as-is, which is kHz for DX, so VHF/UHF/SHF thresholds effectively compare kHz values: VHF 30-300 kHz?! BUG-ish: these tiles basically never match real DX spots; for HAMALERT/POTA frequency in MHz they work).
- Scrolling: screen2ScrollOffset (index into filtered list; reset to 0 when entering screen and on filter change). Right-edge scrollbar x311 w7, track y42..tableBottom, thumb min 14 px, drawn only if filteredTotal>maxRows. Tapping in x>=297,y>=42 zone: above thumb = page up by maxRows, below thumb = page down; no drag, no swipe. Sets redraw via drawDxCluster(). If no thumb (fits), falls through to normal nav (a tap in right column with y>=60 = next screen).
- Redraw: updateScreen2Data (uiTaskLoop every >100 ms): FNV hash signature of count, filters, size mode, footer visible, scroll offset, and the visible rows' time/callsign/freq/mode/country/distance; redraw only if changed and >=5 s since last redraw (rate limit). While footer visible, table drawn off-screen into shared 320x188 16bpp sprite and pushed (no flicker); otherwise direct draw. Fallback without sprite if alloc fails.
- Touch: top-left 50x50 -> filter menu (drawDxClusterFilterMenu L7474): title "FILTERS" size2; "MODE" label; 4 tiles 70x26 at y40: ALL, CW, SSB, DIGI; "BAND" label y82; 12 tiles 72x24 gap6 in 3 rows x 4 cols from y96; CLOSE tile 100x26 at (110,210). Tap toggles (ALL clears mask), sets scroll=0, redraws menu. CLOSE: savePreferences (NVS s2_mode uchar, s2_band uint), inMenu=false, redraw screen. Selection is saved only on CLOSE.

## SCREEN_POTA_CLUSTER (7)
- Purpose: Parks-on-the-Air activator spots. Data: `DXSpot potaSpots[MAX_POTA_SPOTS=30]`, `potaSpotCount`, mutex potaSpotsMutex. Sources: HTTPS API (potaApiUrl default https://api.pota.app/v1/spots) fetched every 180 s (POTA_API_FETCH_INTERVAL_MS L1509; fetchPotaApi L13740, replaces whole array; frequency from API kHz -> stored MHz, band via getBand, mode from API else comment, country from API else QRZ queue) and optionally a POTA telnet cluster (potaClusterHost, default empty; handlePotaTelnetData L16445, addPotaSpot inserts at front).
- Header: accent bar, hamburger, text "POTA.app" (size 2, x35), right time "HH:MM Z" (getLocalTime, i.e. system time, redrawn every update by updateScreen7Clock when sig changes... actually every call of updateScreen7Data, ie every 200 ms, no rate limit).
- Columns NORMAL: UTC@5, CALLSIGN@50, MHz@125, MODE@182, COUNTRY/PAIS@212 (tr(TR_COUNTRY)). ENLARGED same as DX. Cell content: time HH:MM extracted after 'T' in ISO string else first 5 chars (enlarged uses formatSpotUtc); callsign (not truncated in normal); frequency with 3 decimals already MHz; mode; country (maxLen 19 COUNTRY_COL_MAX_LEN, "-" if empty). Same colors as DX. 11/10 rows normal, 7/6 enlarged.
- Filter: screen7FilterModeMask/BandMask using SCREEN2_FILTER_BANDS[9]={ALL,160m,80m,40m,20m,17m,15m,12m,10m}. Menu (drawPotaFilterMenu L7690): title "POTA FILTERS"; mode tiles same as DX; BAND tiles 90x24 gap 6 in 3 cols x 3 rows; CLOSE. NVS s7_mode, s7_band. Saved on CLOSE.
- NO scrolling / scrollbar: shows only first maxRows matching (list of 30 is truncated by rows). Redraw: updateScreen7Data every 200 ms with signature (count, filters, size mode, footer, time/call/freq/mode/country of visible rows); no rate limit. Code comment "SSB only, 10 spots" is stale. updateScreen7() requests redraw upon QRZ/country updates.
- Touch: top-left 50x50 -> menu; global nav.

## SCREEN_HAMALERT_CLUSTER (8)

## Quirks / dead code summary
- drawNavigationArrows empty; TR_HOLD_CAL_HINT and TR_TFT_CALIBRATE_BTN unused; ScreenType 11 (UNLIS) not in order.
- On-device touch calibration never saves; also resets flags on exit.
- DEFAULT button resets only hue. Language change committed immediately and unaffected by CLOSE.
- VHF/UHF/SHF DX filter compares kHz values against MHz ranges (likely never matches on DX screen).
- HAMALERT: no footer drawn, no sprite; POTA/HAMALERT have no scroll (30 buffered, <=11 shown).
- Calibration hint text/threshold inconsistency (3s/5s).
- All clocks show "Z" suffix even if screen1TimeMode is LOCAL (headers always system-time local via getLocalTime; configured TZ offset DEFAULT 0 => effectively UTC).
- Keys for distance/age/band colors do not exist; spot "age" and "distance" are not rendered on these screens.
